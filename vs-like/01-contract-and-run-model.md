# 01：Run 模型与协议契约

## 目标与边界

把共享 `GameRoom` 内的一局生存游戏建模为 Run，定义服务端唯一权威状态及待新增协议语义。不假设任何尚未实现的消息或字段，不在本任务实现客户端玩法。

## 实施步骤

1. 盘点现有 GameRoom、消息契约和状态镜像，确定兼容边界。
2. 设计 Run 生命周期：创建、运行、单人暂停、结算、销毁。
3. 定义玩家、敌人、经验球、升级候选和结算数据的最小字段与事件/快照归属。
4. 为入站请求定义方向、权限、Run 状态和玩家 ID 校验；为出站状态定义版本/完整快照策略。
5. 同步 proto、`messages.json` 与双方生成物，并补契约测试（实现时执行）。

## 依赖与产物

无前置依赖。预计涉及 `server/game`、`server/net`、`server/proto`、`client/Script/Net`、proto/生成文件及对应模块文档。Run/GameRoom 是权威；客户端镜像只读。

## 验收

能表达 Run 生命周期、暂停模式、玩家独立奖励队列、敌人 returning 状态和四项结算；非法玩家选择、过期 Run 请求和错误方向消息被拒绝；契约及生成物一致。
